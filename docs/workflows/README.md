# 开发工作流文档

本目录包含项目各类开发任务的标准工作流程。

## 📚 工作流文档列表

### 核心开发流程

- **[新功能实现流程](./feature-implementation.md)**
  从需求分析到完整实现的全流程
  - **适用场景**：开发新功能、模块
  - **包含内容**：设计、编码、测试、验证
  - **阅读时间**：15 分钟

- **[GitHub API 集成工作流](./github-integration-workflow.md)**
  与 GitHub API 交互的标准流程
  - **适用场景**：开发 GitHub 相关功能
  - **包含内容**：API 调用、错误处理、速率限制
  - **阅读时间**：10 分钟

- **[服务层开发工作流](./service-development-workflow.md)**
  业务逻辑层的开发规范
  - **适用场景**：开发 services/ 模块
  - **包含内容**：设计模式、数据库交互、单元测试
  - **阅读时间**：10 分钟

- **[前端开发工作流](./frontend-development-workflow.md)**
  Web UI 页面开发流程
  - **适用场景**：开发 templates/ 和 static/
  - **包含内容**：模板设计、交互实现、响应式
  - **阅读时间**：12 分钟

- **[数据库变更工作流](./database-migration-workflow.md)**
  数据库模型修改流程
  - **适用场景**：修改 models.py、添加表
  - **包含内容**：迁移步骤、数据迁移、回滚
  - **阅读时间**：8 分钟

### 测试与质量

- **[TDD 测试工作流](./tdd-testing-workflow.md)**
  测试驱动开发的完整流程
  - **适用场景**：所有需要测试的任务
  - **包含内容**：红-绿-重构、测试层级、覆盖率
  - **阅读时间**：15 分钟

- **[Bug 修复工作流](./bug-fix-workflow.md)**
  问题定位和修复的标准流程
  - **适用场景**：修复 Bug、问题排查
  - **包含内容**：复现、定位、修复、验证
  - **阅读时间**：10 分钟

- **[代码审查工作流](./code-review-workflow.md)**
  代码审查和自查清单
  - **适用场景**：提交前自查、审查他人代码
  - **包含内容**：检查项、工具、常见问题
  - **阅读时间**：8 分钟

## 📖 如何使用这些文档

### 作为开发者

1. 根据任务类型找到对应的工作流文档
2. 按照"详细步骤"逐步执行
3. 参考"代码示例"完成编码
4. 使用"检查清单"验证完成度

### 作为 Claude Code Agent

1. 接收任务后，先查阅对应的工作流文档
2. 理解标准流程和最佳实践
3. 按照工作流步骤执行任务
4. 确保所有检查项都已完成

## 💡 典型使用场景

### 场景 1：实现新功能

```
任务：实现"自动下载 GitHub Actions 产物"功能
  ↓
阅读工作流：
  1. [新功能实现流程](./feature-implementation.md) - 主流程
  2. [GitHub API 集成工作流](./github-integration-workflow.md) - GitHub API 部分
  3. [TDD 测试工作流](./tdd-testing-workflow.md) - 测试部分
  ↓
按照步骤执行：
  1. 需求分析（Phase 1）
  2. 设计方案（Phase 2）
  3. TDD 实现（Phase 3）
  4. 集成测试（Phase 4）
  5. E2E 测试（Phase 5）
  ↓
使用检查清单验证完成度
```

### 场景 2：修复 Bug

```
任务：修复"配置保存失败"问题
  ↓
阅读工作流：
  1. [Bug 修复工作流](./bug-fix-workflow.md) - 主流程
  2. [服务层开发工作流](./service-development-workflow.md) - 如果涉及服务层
  3. [TDD 测试工作流](./tdd-testing-workflow.md) - 编写回归测试
  ↓
按照步骤执行：
  1. Bug 复现
  2. 问题定位
  3. 编写失败测试（TDD）
  4. 修复代码
  5. 验证修复
  ↓
回归测试确保无副作用
```

### 场景 3：开发前端页面

```
任务：实现"配置管理"页面
  ↓
阅读工作流：
  1. [前端开发工作流](./frontend-development-workflow.md) - 主流程
  2. [服务层开发工作流](./service-development-workflow.md) - 如果需要新 API
  ↓
按照步骤执行：
  1. 页面设计
  2. 模板创建（Jinja2）
  3. 交互实现（jQuery）
  4. API 集成
  5. 响应式优化
  6. E2E 测试（chrome-devtools）
  ↓
保存截图验证功能
```

## 📋 文档结构规范

每个工作流文档遵循统一的结构：

1. **标题** - 清晰的工作流名称
2. **适用场景** - 何时使用该工作流
3. **前置条件** - 开始前需要准备什么
4. **工作流程** - 分步骤的操作指南
   - Phase 1, Phase 2, ...
   - 每个步骤包含详细说明和代码示例
5. **完成检查清单** - 验证完成度
6. **常见问题** - FAQ 和解决方案
7. **相关工作流** - 相关文档链接

## 🔄 文档更新
